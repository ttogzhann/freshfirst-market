# Render deployment (free proof of concept)

This setup runs the existing production Docker image as one Render Web Service
and uses Render Postgres for SQLAlchemy persistence. It does not use SQLite in
the hosted service, and it does not change the local-development default.

## Blueprint

The committed [`render.yaml`](../render.yaml) is a reproducible starting point:

- Web Service: `freshfirst`, Docker runtime, `free` plan, Singapore region.
- Build context: repository root; Dockerfile: `./Dockerfile`.
- Health check: `GET /healthz`.
- PostgreSQL: `freshfirst-db`, `free` plan, Singapore region, database `freshfirst`, user `freshfirst`.
- `DATABASE_URL`: Render's private `connectionString` from `freshfirst-db`.
- `FRESHFIRST_AUTH_SECRET`: generated by Render; keep it stable across redeploys.
- `FRESHFIRST_ENV=production` and `FRESHFIRST_EXPIRY_DAYS=3`.
- `PORT`: leave unset so Render supplies its web-service port (currently
  `10000`). The image binds that port on `0.0.0.0`; the internal FastAPI and
  TanStack Start servers remain loopback-only.
- `FRESHFIRST_TRUSTED_ORIGINS`: optional when using the standard Render URL;
  the image derives it from Render's `RENDER_EXTERNAL_URL`. Set it explicitly
  to the exact `https://...` origin when using a custom domain or an additional
  approved origin. Never use `*`.

Choose **New → Blueprint**, connect the repository, review the generated
resources, and apply the Blueprint only after confirming the service/database
names and region. No database or service is created by local validation.

## Manual dashboard settings

If the Blueprint is not used, create the following:

1. **New Web Service** → repository → Docker.
2. Root directory: repository root.
3. Dockerfile path: `./Dockerfile`; Docker context: repository root.
4. Region: Singapore (the Web Service and Postgres must share a region).
5. Instance type: **Free** (`0.1 CPU`, `512 MB RAM`); one instance only.
6. Health check path: `/healthz`.
7. Environment: `FRESHFIRST_ENV=production`, `FRESHFIRST_EXPIRY_DAYS=3`,
   `DATABASE_URL` from the database's internal connection string, and a stable
   generated `FRESHFIRST_AUTH_SECRET` of at least 32 bytes.
8. **New Postgres** → name `freshfirst-db`, region Singapore, Free plan,
   database `freshfirst`, user `freshfirst`; copy its internal connection
   string into the Web Service's `DATABASE_URL` reference. Do not use an
   external connection string for same-region service traffic.
9. After the service gets its `onrender.com` URL, either rely on the automatic
   `RENDER_EXTERNAL_URL` fallback or set
   `FRESHFIRST_TRUSTED_ORIGINS` to that exact HTTPS origin. Add a custom domain
   only after updating this allowlist.

## Free-plan constraints

Render's Free Web Service has 512 MB RAM and 0.1 CPU. It can run this
production image for a low-traffic proof of concept, but it spins down after
15 minutes idle and cold starts can take about a minute. Its filesystem is
ephemeral, so SQLite and Docker volumes must not be used for hosted data.

Free Postgres is the durable application store for this setup, but it is only
1 GB, has no backups or managed connection pooling, may restart for
maintenance, and expires after 30 days (with a limited upgrade grace period).
Do not treat this configuration as production data hosting. Export or recreate
only disposable test data, and upgrade the database before relying on it.

The image starts FastAPI and the TanStack Start SSR server in one container,
then exposes only the gateway. Render terminates HTTPS and forwards HTTP to
the container. The same-origin `/api` gateway preserves authentication,
sessions, CSRF protection, account isolation, pantry, recipes, basket,
shopping, cooking, and PostgreSQL transaction behavior.

## Local validation

Build and run only an isolated disposable container and SQLite volume:

```powershell
docker build -t freshfirst:render-local .
docker volume create freshfirst-render-local-data
$secret = python -c "import secrets; print(secrets.token_urlsafe(48))"
docker run --rm --name freshfirst-render-local `
  --publish 18080:10000 `
  --mount source=freshfirst-render-local-data,target=/data `
  --env "PORT=10000" `
  --env "DATABASE_URL=sqlite:////data/freshfirst.db" `
  --env "FRESHFIRST_AUTH_SECRET=$secret" `
  --env "FRESHFIRST_TRUSTED_ORIGINS=http://127.0.0.1:18080" `
  --env "FRESHFIRST_ENV=production" `
  freshfirst:render-local
```

In another shell, wait for `http://127.0.0.1:18080/healthz` to return `200`,
then stop the container. Remove only this test-owned volume after validation:

```powershell
docker volume rm freshfirst-render-local-data
```

Do not run `docker volume rm` against existing FreshFirst volumes. Do not put
Render credentials, database URLs, or generated secrets in this repository.
